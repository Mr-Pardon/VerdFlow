# 策略版本与方案兼容

只维护标准 SemVer `major.minor.patch`，不要增加兼容契约编号或历代版本清单。
策略包发布后不可原地替换，任何字节变化都应发新版本；清单和策略声明版本必须一致。
这里是策略包版本，不是 Studio 应用版本、Schema 版本或 generator 接口版本。

- patch：保持既有角色/构图/参数语义的修复、优化和展示修订。
- minor：兼容扩展。旧方案无需修改即可保留配置含义；新增参数必须有兼容默认值，
  新增可选角色在旧方案中保持关闭，生成器必须尊重 excluded_role_keys。
- major：删除/改名/改变角色职责、改变角色关闭后的构图含义、改变参数单位或数值含义、
  删除参数、缩小范围使旧值非法，或增加必填角色。即使名字与 key 未变也可能不兼容。

例如“关闭铺底后，主景覆盖率从相对铺底范围变成相对整个区域”属于语义改变，
不能仅因为仍然可以解析旧参数而声明 minor。性能优化或符合原有声明的缺陷修复
不要求逐点保持旧结果，但相同完整输入与包仍必须可复现。

Studio 默认解析同策略、同 major、版本不低于方案保存版本的最新已信任正式包，
并再次校验角色和参数；不会跨 major、自动信任或静默修正非法配置。
0.x、预发布和非规范历史版本仅精确匹配。build metadata 不形成自动升级关系。
方案读取不写回；正在执行的任务和历史结果继续使用被冻结的精确包。

## 离线检查

先安装 `PyYAML`，在导出的工具包中运行：

```text
python assets/build_vfs.py new-source output.vfs --previous old-source
```

工具只读取两个源码目录的清单和 YAML，不导入 generator，不依赖运行中的 Studio。
同 major 时会拒绝删除角色/参数、改变 assignment policy/显式 relationship_rules、
新增必填角色、缩小范围和改变已有参数默认值。角色描述、单位与算法内部构图是否改变
仍由作者审查；新增参数默认值是否保留旧语义也不能由工具证明。
没有旧版源码时可正常打包，但不得将“没有比较资料”表述成“已验证兼容”。
