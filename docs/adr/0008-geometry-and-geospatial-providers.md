# ADR-0008：几何与已对齐地理输入

状态：Accepted。适用版本：1.0.0。真实输入的对齐和平台效果仍需用户验证。

## 背景

模型和地理文件能提供相同的规范种植区域，但解析器、坐标前提和高程来源不同。
把它们各自扩展为完整业务流程，会重复 Core 事实与种植逻辑。

## 决策

- Blender 作为用户安装的独立几何 Worker，负责模型事实、区域提取与对应高程能力。
- Blender API 调用限于该运行时脚本；拓扑等可复用纯算法与外部 API 分开。
- 输入 Provider 生成规范 SceneRevision/RegionSet，高程 Provider 生成标准高程增量，
  后续继续使用统一生成、搭配和输出链路。
- SHP/GeoJSON 提供多边形区域，配套 GeoTIFF 提供高程。用户必须保证数值空间、米制
  单位与轴语义已对齐；运行时不猜测 CRS、重投影或自动交换坐标轴。
- 检查必要伴随文件、几何与有限坐标、空间相交、采样范围和 NoData，不把元数据存在
  视为已经验证两份输入一致。地理输入路线与实时 SHP 草稿的格式限制分别说明。
- 原生地理依赖在按需启动的外部 Worker 中加载，不使空闲 Core 依赖完整 GIS 运行时。
- 缓存仅优化重复解析，仍可从受管来源重建，不代替原始事实或进入策略语义。

## 影响与限制

这不是通用 GIS 数据治理或坐标转换系统。范围相交不能证明业务对齐；局部无高程的
处理不能未经决策照搬实时采样的跳过策略。原生解析器、动态插件与其他平台支持需要
独立契约、许可和真实环境验证，不因已有 Provider 端口就视为完成。

## 验证要求

以合成模型和地理文件检查孔洞、MultiPolygon、确定性区域、已知高程、错误拒绝和
Worker 隔离；真实工程只作为本地授权验证，不进入公共样例或提交历史。
