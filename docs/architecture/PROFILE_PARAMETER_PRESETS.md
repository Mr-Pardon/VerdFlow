# Profile 种植参数预设

决策依据：ADR-0006、ADR-0006；策略公开参数定义仍遵守 ADR-0004。

## 文档与所有权

现有 `verdflow.role-binding-profile` v2 可选增加：

```json
"strategy_parameters": {"spacing_m": 4, "coverage_percent": 80}
```

只记录对应精确 StrategyVersion 的公开数值参数，不包含参数声明、控件结构、Seed、选区、
采样或输出信息。键和值由 `planting` 校验；SystemHost 保存/导入时核对策略声明，拒绝未知键、
越界和非有限值。缺省表示纯映射，空对象表示默认参数预设。无额外 Profile 类型或数据库列。

## 保存与交换

Profile Detail DTO 返回 `strategy_parameters: object | null`。两个保存传输入口均支持：

- 不提交字段：创建时无预设，更新时保留预设。
- 提交 `null`：清除预设。
- 提交对象（含空对象）：替换全部预设，而非对旧值进行 patch。

SystemHost 的类型化保存请求用 `replace_strategy_parameters` 区分显式清除和缺省保留。
非空参数对象本身即可明确替换意图。该标志不进入 Profile，也不新增用户概念。
LibraryStore 保存完整 canonical JSON；`.vfp` 交换与 hash 覆盖全部可选值。同步资产信息
或仅更新映射仍保留预设，不依赖 Catalog 提供参数。

## 草稿与执行

UI 选择带预设的 Profile 时用公开默认值加预设初始化草稿，不继承之前的草稿残留。
从方案入口加载无参数的历史 Profile 时同样使用策略默认值重置草稿。用户侧统一为
“种植方案”，新建、更新和另存自动保存完整公开参数，不再提供参数勾选项。临时调整
仅更改本次输入，显式保存才更新可复用值，保存不包含随机种子。

Core 的持久提交和同步协调器使用同一 planting 合成函数，将 Profile 值置于显式运行
参数之下；合成结果进入既有 `generation_args`。未提供的公开值由精确策略版本的默认值
补齐，生成器最终校验不变。实时入口在会话开始时亦冻结同一优先级，不让生成器读取
Profile。历史批次恢复使用冻结请求；选择其当前 Profile 仅恢复候选来源，不应用最新预设。

Profile 编辑不重新生成点位，不改已提交执行请求或既有输出，不产生新版本树。

## 方案展示与复制

方案使用独立卡片与 Profile ID 详情路由，策略版本是信息而不是上级目录。列表摘要
增加 `enabled_role_count`、`asset_count`、`plants`（最多四项）和 `has_parameter_preset`。
缩略图是 App 只读投影，缺失不影响自包含方案执行；请求内共享 Catalog 读取缓存。

保存请求可提供 `source_profile_id` 另存副本。它只作为本次复制的内容基底，不写入新
Profile，也不建立长期依赖。复制必须保持源策略版本和目标；新增植被仍需要当前资产库。

工作台与实时面板在预设路线仅显示方案选择和本次选区；微调进入原有完整配置面板。
两种入口均冻结成现有运行命令，历史恢复不应用当前 Profile 参数。
实时方案选择器向主面板左侧展开独立卡片面板，选择成功后收起；搜索、策略筛选与
方案列表各自保持稳定滚动布局，小屏退化为覆盖面板。该面板只选择方案，不持有
运行状态或独立配置副本。Profile 的临时植被调整以自包含 overrides 冻结，不能回写原方案。

角色相关参数被隐藏后仍保留原值。按 ADR-0004，生成器可依据冻结的角色开关计算内部
有效值，但不能把它回写到 Profile 或命令；恢复角色时继续使用原值。
