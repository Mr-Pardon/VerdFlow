# ADR-0015：Windows 免安装应用更新

状态：Accepted。适用版本：1.0.0。补充 [ADR-0012](0012-desktop-shell-and-user-data.md)。

## 背景

保留 ZIP 免安装交付，同时减少手工替换程序的成本。更新属于桌面基础设施，不应改变
业务契约、用户数据归属或策略信任机制。

## 决策

- Electron 主进程拥有更新生命周期；Studio 通过可选 PlatformBridge 获取状态和发送
  有限命令。Renderer 不传入更新 URL、磁盘路径或任意命令，Core 和 WebUI 不参与更新。
- 构建默认读取桌面壳的 `updates.json`，以 `--update-repository owner/repository` 覆盖
  GitHub Release 来源；`--no-updates` 或空来源不联网。没有公开 Release 是正常检查结果，
  已发布版本缺少更新附件仍按失败处理。
  开发版和浏览器版不执行更新；只接受更高的正式 `x.y.z`，不自动降级或安装预发布版。
- 默认启动后及每六小时检查，发现新版后自动下载；用户可分别关闭这两个选项。
  下载可取消，就绪后必须确认才重启；退出时清理网络、子进程、订阅和定时器。
- 初次下载和更新使用同一 ZIP。发布附件同时提供 `VerdFlow-update-win-x64.json`、ZIP
  和 SHA-256 文件；校验版本、名称、大小、整包及逐文件哈希，拒绝危险路径、链接、重复
  条目、额外文件及超限解压。仅允许 GitHub HTTPS 和受限附件域名，不保存客户端 Token。
- 包内 Python 标准库在同卷兄弟目录准备新版。准备失败不改当前程序；不可写时提示，
  不提权。确认重启前阻止活动任务和打开中的项目，实时服务须先停止，避免丢失会话草稿。
- 隐藏助手握手后等待原应用正常关闭，再备份旧程序、替换并启动新版。替换失败尽力恢复
  旧程序；不自动删除备份。数据根不能位于程序目录内，用户数据、密钥和库不参与替换。

## 影响与限制

SHA-256 是完整性检查，不是独立发布签名；信任根仍为指定仓库与 HTTPS。目前无
Authenticode、离线清单签名、安装器服务或自动数据库回滚。无更新器或无来源配置的旧包
需要手工下载首个已配置版本。完整更新还需要足够的下载、解压和备份空间。

## 验证要求

覆盖损坏包、危险归档、取消、状态恢复、任务门禁、父进程退出前不得替换、替换失败恢复、
外置用户数据保留。隔离助手测试不能代替发布附件上线后的实际跨版本验收。
