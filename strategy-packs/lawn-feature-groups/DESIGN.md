# 草坪点景组团策略设计

状态：Accepted baseline，可安装执行

策略版本：`lawn_feature_groups@1.0.0`

## 1. 构图目标

策略用于以草坪为主体、只需要少量复合植物组团点景的面状绿地。空间关系固定为两层：

1. 主体草坪在固定退距后的 Region 内连续铺设，细粒度边缘草坪补齐退化带。
2. 点景组团在远离边界的内部骨架附近稀疏分布。

每个完整点景组团由零至一株主景植物、2 至 4 株环绕灌木和 2 至 3 株外缘点缀植物组成。
首版不把这些内部构图元素拆成可独立调度的策略，也不在 Core 引入组合调度层。

## 2. Role 契约

| Role Key | 空间职责 | 首版规则 |
| --- | --- | --- |
| `lawn_groundcover` | 主体草坪 | 带受限扰动的六角错列网格，覆盖固定退距后的有效区域。 |
| `edge_groundcover` | 边缘草坪 | 使用独立资产和 0.5 m 中心距，覆盖距边界 0 至 0.5 m 的退化带。 |
| `feature_anchor` | 组团主景植物 | 按公开概率生成零至一株，生成时位于组团中心。 |
| `surrounding_shrub` | 环绕灌木 | 每组 2 至 4 株，3 株为主要概率。 |
| `outer_accent` | 外缘点缀植物 | 每个完整组团 2 至 3 株，优先落在环绕灌木之间的外侧空隙。 |

所有 Role 均采用 `weighted_pool`，允许 Profile 为同一 Role 映射多个植被实例并按权重分配。
策略不记录资产 ID、资产缩放或输出目标信息。

## 3. 草坪生成

草坪使用六角错列网格，而非独立随机散点：

1. 主体草坪以 `groundcover_spacing_m` 为中心距构造等边三角网格，并固定向内退距 0.5 m。
2. 根据稳定 seed 和 `region_id` 派生整体旋转及二维相位。
3. 对每个点施加不超过中心距 16% 的确定性位置扰动，再进行 Region 与边界距离校验，打破机械网格感但保留连续覆盖节奏。
4. 边缘草坪使用独立随机流和 0.5 m 中心距，仅保留距离外环或孔洞边界小于 0.5 m 的点位。

草坪缩放、朝向以及资产候选仍由 Profile 和后续资产分配阶段处理。

## 4. 内部点景位置

策略不直接使用多边形质心。凹形面或带孔面中的质心可能落在区域外，也不能代表可容纳完整组团的位置。

`1.0.0` 使用离散安全空间与均衡责任区选择点景中心：

1. 在 Region 内建立确定性采样网格。
2. 计算候选点到外边界及孔洞边界的最短距离。
3. 按完整组团的真实外缘半径过滤候选点，并根据目标组数推导优选的内部边界舒适距离。
4. 以最大净空位置为起点，通过最远点采样将初始中心分散到尚未覆盖的安全空间。
5. 若舒适区无法达到用户明确的组数约束，则扩展回全部安全候选区继续选点。
6. 对候选点建立 Voronoi 责任区，并进行有限轮带低频权重的质心松弛。
7. 将质心重新吸附到安全候选点，继续满足边界净空和组团之间的最小距离。

这种方法在狭长或弯折 Region 中会自然沿可用空间展开，在宽阔、凹形或带孔 Region
中优先减少远离所有点景的空白区域，不再因为局部净空略大而把组团全部集中在中央宽处。
责任区只用于计算点景中心，不是持久化的 Region、种植边界或 Core 输入契约。

组团数量由 Region 面积、估计最大净空、内部密度基准和公开密度倍率共同推导。每个 Region 单独计算，
不受其他 Region 面积影响。

## 5. 组团模板

组团采用“稳定模板 + 受限变化”，避免全随机极坐标散点形成机械圆环：

- 每个组团按 `feature_anchor_probability` 独立判断是否生成主景植物。
- 有主景时，环绕灌木与主景保持适当半径；无主景时灌木向中心收拢，不留下空心环。
- 真实模型校准后，有主景组团的灌木中心距约为 `1.05-1.45 m`，外缘点缀约为 `1.55-2.05 m`，两层均紧贴主景根部组织。
- 环绕灌木数量概率约为：2 株 14%，3 株 72%，4 株 14%。
- 2、3、4 株分别使用独立的非等角模板。
- 每组整体随机旋转，并对半径和角度施加小范围确定性扰动。
- 外缘点缀植物优先占据环绕灌木之间较大的角度空隙。
- 同一组团中的点共享 `group_id`，便于诊断和后续可视化，但执行侧不依赖该字段组织资产。

## 6. 小面与窄面回退

回退只改变该 Region 的点景层，不阻塞草坪生成：

1. 净空足够时生成完整组团。
2. 无法安全容纳完整组团时仅生成两层草坪，不再生成缺少外围点缀的残缺组团。
3. 主体草坪没有有效点位时，边缘草坪仍可独立覆盖边界带。

首版不为过窄区域强行塞入点景，也不把回退模式、主体草坪 0.5 m 退距或边缘草坪 0.5 m 中心距暴露为用户参数。

## 7. 公开参数

`strategy.yaml` 公开五个结果导向参数：

| Key | 默认值 | 用户结果 |
| --- | ---: | --- |
| `groundcover_spacing_m` | 1.2 m | 控制草坪点位密度和连续覆盖程度。 |
| `feature_group_density` | 3.0 | 控制点景组团的目标数量，默认形成适度连续的点景节奏。 |
| `feature_anchor_probability` | 0.75 | 控制组团包含中央高大主景植物的概率。 |
| `feature_group_min_count` | 0 | 限制每个 Region 的最少点景组数，`0` 表示不约束。 |
| `feature_group_max_count` | 0 | 限制每个 Region 的最多点景组数，`0` 表示不约束。 |

`点景组团密度` 先根据区域尺寸推导自然数量，两个数量参数只在最后按单个 Region
做上下限钳制。当最少数量高于自然数量时，算法可以在不造成组团重叠的前提下自适应
收紧组团中心间距；几何实在无法容纳时不强行达到下限。密度设为零时仍明确输出纯草坪，
不受数量下限影响。

组团内部半径、最小间距、灌木数量概率、点缀数量、责任区尺度和模板扰动保持为算法常量，
避免 UI 与中间计算概念绑定。责任区尺度由每个 Region 的安全面积和目标组数自动推导；
它不改变组团数量，也不控制单组内部植被距离，因此不作为独立用户参数暴露。

## 8. 确定性与职责

一份结果由规范 Region 几何、精确策略包哈希、运行参数、稳定 `region_id` 和 Plant Run seed 共同决定。
Region 在生成前按 ID 排序，各子随机流按用途派生，不依赖 Python hash 或输入顺序。

策略包负责空间构图与目标无关 PointSet v2；不负责资产选择、DTS 或 Blender 高程、XML 导出、缩放和资产存在性。

## 9. 已接受基线

`1.0.0` 已按真实 DTS 场景效果固化以下默认选择：

- 不规则、凹形、带孔和狭长 Region 使用均衡责任区分布，避免集中在单一中心带。
- 主体草坪默认中心距为 `1.2 m`，点景组团密度默认值为 `3.0`。
- 主景植物默认出现概率为 `0.75`，同时保留无主景的低矮组团变化。
- 小型或过窄区域无法安全容纳完整组团时，回退为双层草坪。

暂不新增朝向引导、临路侧偏置或建筑入口语义。这些能力需要额外场景输入，不能由单个 Region 几何可靠推断。
