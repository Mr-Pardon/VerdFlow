# ADR-0002：项目事实、不可变对象与坐标

状态：Accepted。适用版本：1.0.0。

## 背景

区域、点位和输出需要在多阶段之间保持可追溯性。把大量数据散放在可变 JSON 文件中，
或者在多个阶段重复应用位置偏移，会破坏一致性与复现。

## 决策

- ProjectStore 使用 SQLite 保存实体、状态与引用，内容寻址对象保存较大的不可变文档。
- Source Assembly 表达有序来源及其 source-to-scene 变换；SceneRevision 固定已采用的事实。
- RegionSet、PointSet、Binding、Assignment、Elevation 和 Export 通过不可变引用关联。
- 正式点位使用 PointSet v2；高程结果形成保持稳定点位身份与固定字段的后继结果。
- Core 使用未应用最终输出偏移的规范坐标。来源变换属于输入适配，最终输出偏移只由
  输出 Adapter 应用一次，不改写原始点位。
- 地理输入的数值、单位和轴语义由用户在上游对齐，不能因文件元数据而静默换算。
- 精确输入、策略包、参数和种子进入复现边界；展示缓存不能替代正式 Artifact。
- 数据库升级必须显式、备份、事务执行并验证引用，不静默重算或重编号历史快照。

## 影响与限制

“同一策略”不等于跨版本逐点相同；升级算法可能改变结果。复现承诺必须绑定精确输入
和实现版本，坐标与语义容差也应明确。可丢弃缓存不是交换材料或长期业务事实。
任何迁移支持范围必须由对应版本说明和测试确定，不承诺打开任意旧预发布数据库。

## 验证要求

使用合成几何检查变换、点位身份、高程增量和输出偏移；检查对象引用、迁移备份及
失败回滚。公共测试不需要私人地理窗口或真实工程文件。
