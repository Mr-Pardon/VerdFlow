# ADR-0003：宿主、耐久任务与外部 Worker

状态：Accepted。适用版本：1.0.0。

## 背景

模型处理和策略生成可能持续较长时间。页面生命周期、HTTP 连接或短暂的线程阻塞，
不能决定业务任务是否存在，也不能让取消被阻塞在执行队列之后。

## 决策

- SystemHost 管理全局 Library owner 和活动项目；每个项目有专属 CoreHost owner。
- SQLite 连接不跨所有者线程分享；只读查询通过隔离通道读取已提交事实。
- Job、Attempt 和有序事件持久化；幂等输入、租约和 fencing 防止迟到 Worker 覆盖结果。
- 业务任务独立于页面挂载和请求连接，离开后重进应从任务状态恢复锁定与进度。
- 外部 Worker 使用受控输入、结果协议、进程身份和进程树监督，区分心跳与业务进度。
- 取消通过独立 control signal 交给 Supervisor，再按任务状态机持久化；接受取消请求
  不等于底层进程已经退出，也不承诺撤销目标平台已经执行的动作。
- 可信策略默认允许长跑，过长时提示并提供取消；调用方可显式选择执行上限。
- 项目临时目录、子进程、定时器、订阅和锁必须成对回收；对象清理遵守引用与保留策略。
- Local API 绑定 loopback，敏感管理操作有独立授权；loopback 本身不等于安全认证。

## 影响与限制

实时采样和平台 SDK 查询仍可设置必要的单次等待上限，不能将“允许长跑”解释为
不需要检测失联。进程监督不是执行不可信代码的安全沙箱。不同系统的进程回收能力
需要分别验证，不能把单一桌面平台的验证泛化到所有系统。

## 验证要求

测试幂等重试、租约过期、迟到回执、断线补读、页面重入、长任务取消、强杀恢复和
引用安全清理；使用合成 Worker，不向真实用户工程发送破坏性命令。
