# 策略设计方法

## 从效果描述到算法

先把用户的描述拆成四类事实：

1. **构图层级**：主体、陪衬、边缘、填充、点缀等空间职责；
2. **几何关系**：沿边界、围绕锚点、覆盖剩余区域、沿中心线或保持互斥距离；
3. **可调结果**：间距、密度、数量上限、边界退让、簇团半径、随机种子；
4. **资产偏好**：植物名称、体量、颜色与品种，只作为后续 Profile 映射提示。

先完成前两项再定义 Role；资产偏好不得反向决定生成器结构。

## 推荐的生成顺序

1. 校验并按稳定 ID 排序 Region；
2. 规范外环、孔洞与坐标数据；
3. 计算边界退让、有效面积和几何特征；
4. 按依赖顺序生成 Role，例如先锚点、再环绕层、最后填充层；
5. 执行边界、孔洞、最小距离和重叠校验；
6. 对不可满足的 Region 使用声明过的降级规则；
7. 生成稳定点位 ID，并返回 PointSet v2；
8. 由 VerdFlow 后续流程通过 Profile 解析为具体资产。

## 参数设计

只公开用户能够理解并通过预览判断的参数。优先使用有明确物理含义的单位，例如米、数量、比例和角度。

好的参数示例：

- 点位间距；
- 边界退让距离；
- 每个锚点的陪衬数量；
- 聚落半径；
- 单 Role 数量上限；
- 抖动比例。

避免公开依赖实现细节的魔法系数。多个底层常量共同表达一个视觉效果时，应封装成一个结果导向参数。

## 几何降级

策略不能假设 Region 总是宽阔、规则或无孔洞。为每种主要几何限制明确降级顺序，例如：

1. 正常执行全部构图层级；
2. 缩小非关键层级的数量或半径；
3. 禁用非必需 Role；
4. 对过小区域返回合法零点结果。

不要通过越过边界、忽略孔洞或无限重试来强行达到目标数量。降级行为应写进策略 README，并进入测试。

## 确定性与随机性

随机效果必须来自传入的 `seed`，并使用稳定的遍历顺序。不要使用当前时间、系统随机源、文件顺序或哈希表遍历顺序作为隐式随机来源。

固定种子用于复现和回归；更换种子用于观察构图变化。随机性只能改变允许变化的布局，不得破坏 Role 关系和几何约束。

## Agent 辅助迭代

每轮迭代保留并向用户说明：

- 使用的 Region 样例及其关键几何特征；
- 参数和随机种子；
- 每个 Role 的点位数量；
- 成功、降级或零点结果；
- 用户认为不符合预期的可观察空间现象；
- 本轮只修改了哪条算法规则，以及预期影响。

不要仅凭一张效果图持续堆叠特例。先把反馈改写为可验证的空间约束，再修改算法并补充测试。策略源码、契约和测试是最终可复用成果，聊天上下文不是策略的一部分。

## 单一职责

生成器只负责“根据 Region、参数和种子生成 Role 点位”。以下职责应留在其他层：

- Agent 或用户负责解释需求与迭代算法；
- Profile 负责 Role 到资产的映射、权重和缩放；
- Worker 负责高程采样或目标软件能力；
- Adapter 负责目标格式导出；
- Studio 和其他应用负责交互与预览。
