# 策略验证清单

交付前逐项确认：

1. 清单是合法 JSON，文件路径已排序，分发文件集合闭合且无额外文件。
2. `strategy.yaml` 能通过 Strategy v2 校验，所有生成点的 `role_key` 都已声明。
3. 相同完整输入（Region、随机种子、参数、角色开关和策略包）产生语义及字节序列均稳定的 PointSet 结果。
4. 调换输入 Region 的顺序，不会改变每个 Region 自身的生成结果。
5. 所有点均位于外环内部且避开孔洞；狭长、小面积和凹多边形也经过测试。
6. 空 Region 或不可生成的 Region 返回合法的零点结果，或边界明确、可理解的错误。
7. 参数的 `min`、`max`、`default` 和 `step` 相互一致，极值不会导致无界循环或异常规模输出。
8. 点位 ID 唯一，`point_count` 等于点位数组长度。
9. Strategy 输出中没有泄漏目标资产、Catalog、Profile、DTS 或 Blender 标识。
10. 每个 Role 都能用一句话解释其空间职责；不存在仅因植物种类不同而拆出的 Role。
11. 多资产映射不会改变 Role 的点位生成规则。测试合法角色开关组合，明确关闭支撑或锚点后的构图；配置至少一个角色启用，启用的必需角色仍须有完整映射。
12. 固定种子用于回归测试，另外使用多个种子检查结果差异是否仍符合构图意图。
13. 提供用途展示时，按 `role-presentation.md` 检查完整角色覆盖、唯一分组、示意坐标、文本和符号限制；名称与职责只来自 `roles`。
14. `.vfs` 导出再导入仍保留展示声明；不存在需要改 Studio、SystemHost、Core 或实时面板才能识别该策略的专属表或分支。
15. 声明 `filter_equivalent` 时，对每种开关组合逐点比较完整生成后过滤结果，包括 ID、顺序与旋转；不声明时按策略预期检查重新构图、边界和固定输入复现，不强制等价。
16. 关闭角色后不改写隐藏参数，重新启用恢复原结果；内部有效值不泄漏进 Profile 或执行参数。即使策略忽略开关，Core 最终点集也不能包含关闭角色。
17. 若提供参数示例，按 `parameter-preview.md` 验证适合本策略的单一样本、米制尺度、固定种子、极值预算、角色过滤和原生成器逐点一致性；示例随 `.vfs` 保留，无 UI 专属代码。

为几何辅助函数编写聚焦测试，并至少提供一个端到端生成器样例。已知风险较高的算法还应覆盖边界退让、孔洞、重叠消解和降级路径。不得把真实保密项目模型作为提交到仓库的测试夹具。

完成检查后，使用工具包中的 `assets/build_vfs.py` 创建 `.vfs`。构建成功只代表源码目录和归档结构合规；VerdFlow 导入时仍会重新校验 Strategy v2，并在执行前要求用户显式信任。
