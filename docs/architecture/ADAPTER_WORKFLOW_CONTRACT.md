# Adapter 能力与输入链路契约

状态：Accepted（内置注册、受限解析与显式采样绑定已接入；通用插件机制未开放）
决策依据：[ADR-0024](../adr/0024-adapter-recipes-and-sampling-bindings.md)

## 1. 范围与实现状态

本文约束后续内置 Adapter 扩展：按能力实现，按推荐链路组织入口，按标准事实连接主链。
“必须 / 不得”是实现和评审门禁，不表示当前产品已经提供通用工作流编辑或插件安装。

2026-11-05 的运行迁移保持 HTTP 接口、数据库结构及面板交互不变。Contracts 已提供
`CapabilityRef`、`InputRecipe`、`SamplingSourceRef`、`SamplingBinding` 和
`ResolvedPlantWorkflow`；宿主注册与执行服务消费这些类型。下文仍包含后续扩展门禁，
不能把尚未实现的配置表单、插件 SDK 或任意对象直接当作公开 HTTP 参数。

FBX、SHP/TIF 和 DTS 实时链路已接入内置 Registry。输出通过与其他 Provider 对称的
`CoreHostExtension.export_providers` 注册；原 SystemHost 静态路由表已移除。新采样采用
独立 v2 命令，旧 v1 命令保留原语义。第三方加载、通用面板、区域双入口合并和影像输入
均不在本轮范围。

2026-11-09 影像准备由 Geospatial Adapter 提供独立的 Region Source Provider 和
`verdflow.imagery-regions`。Studio 提供专用入口，WebUI 保持不变。标准 Windows 免安装包
随包提供固定模型与 CPU 运行库，开发态可由本地配置启用识别；不开放第三方加载或通用交互扩展。

影像输入不按整幅像素数拒绝；解码块、实际磁盘和 Worker 内存仍受资源预算约束。
固定网格概率融合逐块落盘，再拼接四连通区域。Studio 新任务不在识别时剔除小面；
验收以全图候选叠图为主，按原图区域像素数筛选，并保留手动排除状态。按需查找对筛选结果
全局排序后再分页，原候选批次仅用于定位几何，不决定界面分页。确认只提交
可见且选中的区域 ID，正式边界不使用预览简化结果。已执行的旧任务不重算，旧参数
`min_region_pixels` 已剔除的区域不属于其候选。既有非影像链路保持不变。

候选几何、指标与复核索引按原来的 v1 Artifact 写出；大候选使用临时索引排序和分批
写入，不改变区域 ID 或选择契约。确认子集流式读取并保留原始边界，全部确认复用原
Artifact；新区域集及工作流状态原子发布。正式细化与识别共享 Windows 动态内存预算，
监测实质处理进展，不限制持续有进展的任务总耗时。停止或失败不覆盖已有范围。

影像验收的近景细节是只读显示投影。SystemHost 按成功 Job 的绑定解析原始影像与精确候选
Artifact，Geospatial Adapter 的独立读取进程按原始像素网格产生底图和候选 ID 瓦片。
Studio 按视野和像素密度选择层级，保留有界的会话内缓存；不改写原影像、不生成业务 Job，
不修改候选、像素计数或最终 RegionSet。细节未到达或读取失败时保留现有全图概览。
大候选由瓦片进程建立可丢弃的空间索引，构建与请求等待分离，客户端就绪后再读取瓦片；
旧候选无需重新识别。

「细化种植范围」预览是 Studio 的只读叠图。现有影像瓦片接口可附带绿度或斑块参数，
独立读取进程从原始 RGB 与冻结植被掩膜计算原像素上的拟留白，再投影到当前瓦片。
最小留白斑块接收任意非负像素数。小阈值使用近景局部读取，大阈值在同一隔离进程内后台
分块统计跨瓦片的连通面积，并缓存当前参数对应的临时索引；不扩大单次栅格读取范围。
近景才计算，Studio 只给保留候选着色。确认入口不变：关闭细化沿用确认 v1，开启后
确认 v2 冻结原候选选择与细化参数。Geospatial Adapter 独立进程裁掉选区内的拟留白，
按原图像素过滤裁后碎面，输出精确 Region 几何与指标。Core 成功验证并原子激活新
RegionSet；失败或取消保留旧范围，不重跑模型。回看从确认任务恢复原候选选择与参数，
不把裁后碎面的 ID 当作候选 ID。

确认后仍可返回影像验收。原识别 Job、SceneRevision 和精确候选不变；重新确认通过
`verdflow.revise-region-source-selection` v1 记录原候选和基准区域集，派生并激活新的
RegionSet，不覆盖旧版。未结束的种植任务或已确认的种植批次只允许回看，避免清空当前组合。

### 1.1 当前实现与过渡边界

- 内置链路为 `verdflow.fbx-regions`、`verdflow.vector-regions`、
  `verdflow.dts-live-selection`。准备阶段仍调用既有 Scene Preparation / Region Source
  用例，并通过同一个 Registry 检查能力；不把 FBX 多阶段处理压缩成单 Job。
- 现有 SceneRevision/专用入口尚未持久化独立 recipe 选择，统一由 Registry 的
  `legacy_importer_ids` 桥接；只有唯一匹配才解析。新多入口应显式提供 `recipe_id`，不能
  继续增加 SystemHost 私有路由表。匹配发生在新提交/首次输出确认，不在已冻结任务恢复时。
- 现有矢量入口仍要求一份矢量和一份 TIF；`source_member_kind` 声明默认 elevation 槽位。
  匹配零项或多项都拒绝，不按文件顺序选择。v2 GeoTIFF 采样只接收绑定的 TIF，不再要求
  矢量文件。服务级支持登记另一份对齐 TIF 并派生新结果；暂不新增替换高程的 UI。
- 工作台矢量入口可显式提交 `verdflow.region-source.command` v2。Provider 声明支持后，
  Worker 仍产出相同 Region 文件，项目宿主调用 Core 完成验证和定版。Job 成功、
  SceneRevision、RegionSet 和工作流激活在同一 ProjectStore 事务内可见；失败或提交前
  取消不会激活结果。v1 保持显式定版，影像候选不接受自动定版。
- FBX 绑定精确的已准备 SceneRevision，保留原 Region member 筛选与场景缓存；当前不开放
  跨 FBX 场景替换。DTS 绑定 connector session、operation 和 generation token，沿用
  授权端口及场景校验。其 Source hash 标识操作输入，不代表外部实时地形不可变。
- 配置带精确 schema 身份并在契约层检查 JSON、安全字段和数值；格式及采样参数的领域
  校验继续由对应 Adapter 执行。本轮不引入通用配置 schema 编辑器。
- 实现身份使用内置 Provider 版本及命令契约版本；尚未冻结插件代码制品，不能承诺跨产品
  版本重放完全相同的算法代码。

### 1.2 冻结协议与保留

`verdflow.sampling-binding` 和 `verdflow.resolved-plant-workflow` 均为 v1 值对象。
携带显式绑定的 `verdflow.elevation-sampling.command` 使用 v2；原命令 v1 不重写。
带 workflow 的 Plant Run request 使用 v6（旧 v5）、continuation 使用 v2（旧 v1），
composition output request 使用 v2（旧 v1）。不含绑定的旧请求保留原版本和恢复路径，
不能在旧版本正文里偷偷加入 workflow。Worker 调度命令身份仍沿用现有命令，不新增进程。

运行请求/continuation Artifact 保存 recipe 内容 hash、精确采样与输出能力、来源内容
身份、配置、对齐前提和失败策略；输入点及 Assignment 仍由现有阶段字段与谱系关联。
重试确认读取原 continuation，不重新选择最新默认值。更换采样源需显式创建新采样执行；
现有批次中已定版的高程点集继续复用其自身生产命令证据，而不是自动重新采样。

引用仍由现有关系保留：Source 保留原始 Artifact、Assembly 保留成员、SceneRevision
保留 manifest、运行表保留请求/continuation、PointSet 保留生产 Job。没有只写 JSON 的
孤立临时地形文件，也没有增加独立持久化表或新的后台资源所有者。

## 2. 稳定术语与所有权

| 概念 | 职责 | 不拥有的职责 |
|---|---|---|
| Adapter | 集成包，提供一个或多个 Provider，可附带推荐输入链路 | 不接管 Core、Store 或任务状态机 |
| Provider | 可调用的类型化能力，具有固定输入输出契约 | 不因属于同一个包而隐式共享输入事实 |
| Input Recipe | 有限输入链路，声明准备流程、数据槽位、默认高程能力与绑定关系 | 不包含任意脚本节点，不执行空间算法 |
| Sampling Binding | 指定采样能力所用的地形事实或受控会话及配置 | 不修改区域来源，不从文件顺序猜测高程 |
| Output Target | 输出平台、目标资产契约与输出能力 | 不属于输入格式，不等同于文件扩展名 |
| Resolved Workflow | 宿主解析并由 Core 冻结的本次实际选择与数据引用 | 不随 Registry 或链路默认值变化而重新解析 |

Provider 的身份至少由能力种类、Provider ID 和契约版本确定；Adapter ID 是归属信息，
不得以“来自哪个 Adapter”代替“执行哪个能力”。既有不同能力注册表可以保留相同 Provider
ID；引用时仍必须消除种类歧义。Provider 协议版本与实现版本分开记录，不能套用策略包的
同 major 自动兼容规则。

Contracts 定义共享值对象；Core 校验事实、谱系和阶段不变量；Adapter 解析外部数据并执行
算法；SystemHost/CoreHost 负责能力注册、运行条件与组合；Renderer 只消费受审产品投影。
外部 SDK、文件解析器和本机路径在 Adapter/宿主边界终止，不能进入 Core 算法。

## 3. 能力声明

能力描述必须包含下列语义。执行实现由已注册 Driver 提供，描述文档本身不是可执行代码。

| 字段语义 | 约束 |
|---|---|
| 身份 | 能力种类、稳定 ID、契约版本、所属 Adapter 及可追踪实现身份 |
| 输入/输出 | 支持的标准事实及版本；需要时明确 polygon 或 polyline，不隐式转换 |
| 资源要求 | 有名称、类型、数量和必需性的槽位，例如影像、高程栅格、场景几何或实时会话 |
| 配置 | 具有确定 schema 的配置，明确默认值、范围及不支持项 |
| 坐标要求 | 接受的规范坐标及对齐前提；声明不能视为实际对齐证据 |
| 运行条件 | 所需运行环境、会话能力及支持的恢复方式 |
| 执行归属 | 已注册的命令类型、版本及唯一 Worker/Driver 所有者 |

同一 Adapter 可提供多个输入、高程或输出 Provider，不要求为每种文件扩展名单独拆包。
相同业务操作下的 SHP/GeoJSON 可以共用能力；需要不同准备过程和配置的影像提取可单独声明。
同一个 Worker 可以承接多项能力，但命令必须有唯一执行归属，不能根据 UI 页面猜测处理器。

## 4. 推荐输入链路

Input Recipe 必须具有稳定 ID、版本、所属 Adapter、准备能力引用、结果几何种类、资源
槽位、默认采样能力引用和明确的数据绑定规则。引用的能力可以由其他已注册 Adapter 提供；
引用只建立公开契约依赖，不允许导入其他 Adapter 的私有模块或自动下载其代码。

准备流程只能引用已注册、受控的准备能力或已有准备用例。FBX 的模型检查、材质确认与区域
提取可作为既有准备用例被引用，不必被压缩成一个 Job，也不引入任意步骤脚本或通用 DAG。
链路定义声明哪些准备结果满足资源槽位；具体不可变引用在准备完成后校验并冻结。

所有链路进入种植前必须定版为标准 SceneRevision 和 RegionSet，或对应的 PathSet。
两类面入口继续保留不同前置条件，并共享结果定版规则；不能伪造材质、场景或路径来源。
链路不得绕过策略信任、资产分配、Review、高程结果校验或输出谱系校验。

链路可提供默认采样绑定；产品可以仅开放该默认组合，不强制第一版提供自由替换 UI。
默认值不是执行时搜索规则：提交后不得重新按 importer、文件名、扩展名、成员顺序或最新
Registry 内容选择采样来源。相同格式的多个源必须通过明确槽位区分。

### 4.1 输出独立

输入链路不得必须包含某个平台输出实现。DTS XML 是目标平台能力，不是通用“XML 输出”。
产品模板可以推荐或限制输出平台，例如绑定当前会话的 DTS 实时工作流；限制必须明确可查，
不能藏在输入 Worker 或高程 Worker 中。

目标平台应在目标资产搭配与 Assignment 前确定。更换平台必须重新验证对应资产契约并生成
匹配的分配事实，不能把原 AssignmentSet 原样交给另一个输出 Provider。输出仍只消费标准
点位与兼容 Assignment；项目偏移仅在最终输出阶段应用。

### 4.2 推荐链路示例

下表表达组合关系，不宣称未实现的能力已可使用。

| 输入链路 | 准备能力 | 默认采样来源/能力 | 输出选择 |
|---|---|---|---|
| 矢量区域 | SHP/GeoJSON -> RegionSet | elevation 槽位 / GeoTIFF 采样 | 独立选择已验证目标 |
| 影像区域（Studio） | RGB GeoTIFF -> 候选掩膜与区域 -> 确认定版 | 显式 elevation 绑定 / 同一 GeoTIFF 采样能力 | 同上 |
| FBX 区域 | 既有 Scene Preparation -> RegionSet | 准备所得场景几何 / Blender 采样 | 同上，现有产品为 DTS |
| DTS 实时 | 受控选区或路径事实 | 当前指定场景会话 / DTS 采样 | 产品模板可限定 DTS |

矢量与影像入口可共享同一高程能力，不能复制两套高程实现。影像提取不需要读取高程文件
才能产出区域；一次选择影像与高程属于产品便利，不是输入算法的强制依赖。

试验入口复用版本化 Region Source 提交与定版，通过独立命令身份、固定模型 profile 及
显式影像成员引用识别，不用 importer 桥接。候选结果未确认前不激活项目区域；掩膜和区域
经 Job Artifact 保留，不保存模型本地路径。Studio 仅提交保留的区域 ID，宿主从该候选派生
选定几何与指标 Artifact；定版后原候选不变。项目重开由已有 Job 投影恢复验收，未确认的
面板选择不是项目事实。后续从来源 manifest 读取精确 recipe 和高程成员，解析为既有采样
绑定；已确认项目不依赖重新加载模型。该切片没有通用交互状态或面板注册契约。

## 5. 显式采样数据绑定

高程是平级能力，其依赖为“待采样点 + 明确地形来源 + 配置”，不是“产生区域的输入模块”。
同包的区域提取和采样可以共享场景缓存、进程或会话，但共享不能成为未记录的数据来源。

Sampling Binding 必须包含：

- 精确的高程能力引用，以及配置 schema 版本和已校验配置。
- 明确的资源槽位与采样来源引用，引用必须属于当前项目的受管事实或当前受权会话。
- 与生成点坐标框架的关系，以及对齐依据；缺少可执行对齐依据时不能自动尝试重投影。
- 缺失高程、范围外和会话失效时的明确处理策略，不能由调用方临时猜测。

来源必须采用可区分的类型，不能把本机文件路径或无结构参数字典当作来源：

| 来源类型 | 必须记录的事实 |
|---|---|
| 不可变资源 | 已登记 Source/Artifact 引用及内容身份；需要时指定 Assembly member |
| 场景派生资源 | 精确 SceneRevision、受管几何/场景证据及所需对象选择，不要求统一转成 TIF |
| 实时会话 | 受控会话和场景身份、可用的场景修订证据及有效期语义；不保存凭据 |

TIF 波段、Blender 采样对象与射线参数是各 Provider 的类型化配置，不成为 Core 的通用算法。
真实会话未提供不可变场景版本时，应记录其复现限制，不能编造内容 hash。恢复时须重新确认
指定会话/场景有效，不得自动连接另一个当前场景；已采样并定版的结果仍是独立事实。

区域来源与采样来源可不同，但二者不能被偷换：RegionSet 的来源谱系保持原样，采样结果
必须另外追踪 Sampling Binding。新增辅助高程 Source 不等于允许替换项目固定几何输入，
也不放宽单一当前工作链；其注册和引用仍经 Core/Store 用例。

采样保持点 ID、Role、原生成位置、旋转及分组不变，只派生允许的高程字段。不同输入点位
schema 的支持必须显式声明；不因存在 PathSet 就声称全部采样器已支持路径点位。

### 5.1 坐标与失败策略

地理输入继续由用户提供已对齐的米制数值。记录元数据、相交范围或相同 EPSG 不等于验证
真实空间一致；未知 CRS 不自动成为错误。影像与高程不必同分辨率，必须各用自己的空间
定位，不能把像素行列直接互相对应。XY/Z 单位和高程基准由来源与 Provider 前提说明，
不从 TIF 后缀推断；自动重投影、轴交换和高程基准转换仍需另行决策。

现有失败策略不会在本轮被统一改写：GeoTIFF 对范围外/NoData 明确失败；Blender 未命中
可保留生成位置并记录 hit=false；DTS 按已有实时部分成功规则执行。任何替换必须同时验证
输出 Provider 对这些结果的接受条件，不能宣称“可选采样器”就代表所有语义等价。

## 6. 解析、冻结与重跑

SystemHost 校验用户选择和机器运行条件，Core 校验并冻结项目引用。解析后记录必须覆盖：

1. 实际输入链路 ID、版本与内容身份；不是未来再查询的“最新版本”。
2. 实际 Provider 种类、ID、契约/实现版本及可验证的实现身份。
3. 已定版 SceneRevision、RegionSet/PathSet、精确策略和目标分配引用。
4. 实际采样来源、配置、坐标关系和失败策略。
5. 实际输出目标/能力、导出选择与最终偏移。

冻结时机遵守既有分阶段执行：准备完成后冻结规范输入；生成和映射提交时冻结其依赖；
按需输出确认时冻结采样与输出 continuation。不能要求用户在创建项目时就指定所有导出
参数，也不能在已经冻结的阶段修改请求。最终结果必须能沿引用追溯完整解析记录。

更换采样来源或配置产生新的采样执行与派生结果，不覆盖历史 PointSet；无需仅因更换 TIF
重算与之无关的区域和生成点。更换输入提取配置产生新的区域事实，旧点位不得冒用新区域
身份；更换输出平台必须处理资产分配兼容性。改变已确认组合的当前状态仍走既有版本/续跑
用例，不开放任意阶段倒退。旧 Job 不重写、不按新默认值恢复。

精确版本不可用或绑定失效时明确停止/要求用户重新配置，不能静默改用同包其他能力。
当前没有通用插件制品冻结机制；在建立精确实现解析和恢复证据前，不得承诺跨版本代码重放。
关键资源引用必须进入引用保留/清理关系，不能只把 ID 放进无人维护的 JSON。

## 7. 注册、验证与错误语义

注册阶段必须检查身份冲突、引用闭合、能力种类、契约版本、唯一命令归属、资源槽位绑定
和配置 schema。只有已注册且可执行的能力可以用于解析；声明不授予信任、权限或安装授权。
输出能力应具有与区域/高程能力对称的增量注册方式，但不能替换 Host、Store 或 Core 服务。

提交阶段必须检查：

- 准备流程实际产生的事实种类与策略 `input_geometry` 相符。
- Source/Artifact/member/scene 引用真实存在、归属正确且内容版本匹配。
- 高程槽位已明确绑定；有多个候选时不猜测，缺失时不以输入主文件替代。
- 坐标前提、运行环境和实时会话满足所选能力要求。
- 输出目标与 Catalog/Profile/Assignment 的平台及 schema 一致。

注册和提交校验不能替代结果校验。Core 仍核对点位谱系、不变量和正式 Artifact；Adapter
负责格式、几何、数据读取及其算法必要校验。受信任的内部产物继续按已有边界避免无意义
的全量重复验证。

错误至少区分：能力缺失/版本不支持、资源缺失/多义、坐标前提不满足、目标资产不兼容、
会话失效、执行失败及取消。传输错误应有稳定错误码和类型化安全上下文；正式编码随对应
接口实现确定。用户提示必须说明阶段、原因和下一步操作，不显示敏感本机路径或堆栈。
UI 错误允许关闭，关闭只清除提示，不篡改失败任务或重新授权执行。

配置类错误不自动重试。临时运行错误只有在已冻结资源和权限仍有效时才能按既定策略重试。
链路失败不意味着事务性撤销已经交付到外部场景的对象，不能承诺当前没有的自动回滚。

## 8. 生命周期与 UI

链路定义不拥有进程、缓存或 SDK 对象。Host 管理任务；Worker/Connector 按现有所有权
管理子进程、会话和临时资源。共享资源使用明确的 owner/使用期，取消一个任务不得关闭
另一个任务仍使用的资源；超时、取消、崩溃和宿主退出都有配对清理。
大体量几何和像素通过 Artifact 或受控缓存交换，不能写入链路描述或跨进程消息正文。

FBX 的专用材质面板可以保留；SHP 与影像可以有不同的准备交互。专用 UI 不得执行算法、
管理事实或自行选择 Provider。后续能力投影可给出标准阶段和已注册准备视图标识，不能把
Adapter HTML/JavaScript 注入 Renderer，也不要求本轮实现通用动态表单。

## 9. 迁移顺序与验收

| 顺序 | 工作 | 可交付条件 |
|---|---|---|
| A | 固定本文与 ADR 的语义边界 | 文档明确目标/当前差异，不宣称运行功能已上线 |
| B | 类型化描述、内置注册和受限解析 | 单包多能力、跨包引用、未知/冲突/缺依赖均有服务级测试 |
| C | 采样绑定与执行快照 | 版本化命令、引用保留、续跑/恢复和旧项目兼容通过测试 |
| D | 影像输入接入 | 新旧地理入口复用同一采样器，算法/性能与真实坐标验收通过 |
| 后续 | 通用面板、更多目标、第三方安装 | 分别满足产品需求、目标验证和独立安全决策 |

阶段 B/C 可以分片交付，但不能在 C 未完成时声称支持独立采样来源。实现过渡允许保留
集中、明确的 legacy 路由，继续从旧场景解析旧 Job 的输入；新链路不得扩大按 importer
推断采样资源的做法。解析请求/continuation/命令变更须评估 schema 和迁移，不原地重释 v1。

最低验收案例：

- 同一 Geospatial Adapter 注册矢量和影像两个输入能力，两条链路引用一个 TIF 采样器。
- 两个同为 GeoTIFF 的资源被明确区分，交换列表顺序不改变绑定；资源缺失或多义被拒绝。
- 相同生成点切换另一份已对齐高程后 XY/身份/角色/旋转不变，产生可追踪的不同采样结果。
- 链路默认值、Provider 注册或源文件变化不改变已冻结运行；旧任务依旧按旧谱系恢复。
- 缺失精确能力实现、错误 target、polygon/polyline 不符和失效会话均不会启动错误阶段。
- 输出扩展通过受限注册接入，不能替换基础服务；未实现目标不因声明存在而被标为可用。
- FBX 准备/提取、高程采样、SHP/TIF、DTS 实时、批次输出与取消恢复基线无回归。
- 采样引用保留、缓存回收、共享会话取消隔离及失败提示关闭均有验证。

这些是完整目标的门禁，不表示所有未来入口已经实现。当前服务级验证覆盖单采样器被两条
声明引用、跨包引用、注册冲突/版本/几何/多义资源拒绝，真实 GeoTIFF 子进程切换高程且
保留点位不变量、运行快照重开和垃圾回收保留，以及既有 FBX supervisor、DTS 实时面/线、
批次延迟输出和取消清理。FBX 测试使用协议 Worker 替身；本轮未重新操作真实 Blender/DTS
场景，也没有影像提取算法验收。
