# ADR-0001：模块所有权与应用边界

状态：Accepted。适用版本：1.0.0。

## 背景

多个交互入口和外部运行时需要复用同一条种植主链。按页面复制业务代码会使扩展策略、
替换平台或排查任务状态时出现多份规则。

## 决策

- Python Core 编排项目、任务和领域用例；TypeScript 应用负责交互和展示。
- Contracts 只定义稳定类型、命令、结果和事件，不引用存储或平台 SDK。
- Planting 持有目标无关策略执行与通用搭配解析；存储和进程监督由各基础设施包持有。
- Adapter 实现外部协议并消费 Core 端口，Core 不反向依赖 Blender、DTS、HTTP 或 UI。
- Studio、WebUI、CLI 及未来入口通过公开用例消费能力，不自行访问项目数据库或复制算法。
- Local API 是传输与组合入口；SystemHost 管理应用级生命周期，不替代 Core 业务编排。
- 可选只读展示投影与写入主链隔离，不成为第二份项目事实源。
- 共享 UI 包属于应用展示层，通过窄接口消费数据，不导入某个应用的私有控制器或传输实现。
- 每个模块维护职责、公共入口、依赖方向、验证方式和限制；跨包只使用明确公共入口。

## 影响与限制

扩展应优先组合已有规范事实和类型化 Provider，而不是增加平台专属 Core 分支。
新建模块必须有稳定职责，不能只为转发一个函数制造抽象。预留 MCP 或其他 Bridge 边界
不代表所有入口都已实现；当前版本不承诺任意用户插件的动态安装和安全隔离。

## 验证要求

检查依赖方向、公共导入、Renderer 的存储隔离，以及新入口是否复用同一用例。
替换展示或传输组件不得改变策略、坐标、资产分配和正式输出语义。
