# ADR-0004：策略契约、角色与显式信任

状态：Accepted。适用版本：1.0.0。

## 背景

用户需要独立编写空间算法，不应被迫理解平台资产、界面绘制、相机或数据库。
与此同时，可安装的 Python 策略代码不能因为包结构正确就获得执行权限。

## 决策

- 策略输入是规范区域、参数、固定随机种子及角色开关；输出是目标无关的角色点位。
- 策略声明角色与公开参数，角色语义绑定精确策略版本，不保存目标资产定位。
- 同一精确包和完整输入必须可复现；不依赖未冻结的外部服务或隐式随机状态。
- 策略自行决定关闭角色后如何调整空间构图。Core 始终过滤关闭角色，不为具体策略
  改写隐藏参数，也不推断剩余角色的覆盖或间距。
- 控件可见性由包的角色关联声明驱动；隐藏或关闭不等于清除用户已经保存的值。
- “完整生成再过滤等价”只是可选承诺，不限制所有角色感知策略都使用同一构图方式。
- 执行前按精确包 hash 检查信任，复制并核对本次包内容，再通过 Worker 运行。
- 批量信任须由用户显式确认本次包集合，不能连带信任未来版本。
- 策略版本遵循 [ADR-0016](0016-compatible-planting-plans.md) 的语义兼容承诺；
  版本可兼容不等于包已信任，也不保证新旧算法的点位逐点相同。

## 影响与限制

策略作者只承担算法和必要契约；可选展示声明不引入第二个预览生成器。
格式校验、hash 一致和已被信任均不证明代码无恶意。当前进程隔离是生命周期手段，
不是对任意第三方代码的系统级权限沙箱；用户应只信任来源可审查的策略。

## 验证要求

测试固定种子、边界和孔洞、角色开关、参数校验、原始结果验收、Core 过滤、精确包
信任及撤销。新策略不应要求 Studio 或 Core 增加按策略 ID 分支的逻辑。
